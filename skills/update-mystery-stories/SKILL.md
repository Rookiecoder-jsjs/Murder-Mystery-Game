# 剧本创作与更新

把用户的主题变成可运行的原创案件、公开美术资源和可追溯的交付记录。用户只给主题时，也应完成本地创作、生图、集成和检查，不停在故事提纲。

这是本项目专属 skill，源码在仓库 `skills/update-mystery-stories/`，通过项目 `.agents/skills/update-mystery-stories` 的相对链接发现。保持项目作用域，不安装或复制到用户、管理员或其他全局技能目录。

## 确定范围

- 找到含 `backend/app/content/stories/manifest.json` 的项目根目录，先读仓库规则并检查 Git 状态。优先使用当前工作区；不要依赖本机硬编码路径。
- 区分新增、正文修订、仅配图更新、发布现有成品。新增生成标准 UUID；修订保留故事 UUID 和已有角色、线索 ID。仅配图更新保持正文逐字不变。
- 尊重用户主题、时代、风格与人数。未指定人数时按关系和推理需要选择 3—8 人，包含真人玩家，受害者不计入；说明选择理由。缺少非关键偏好时自行作合理设计，不重复索取确认。
- 默认产出一部中文原创故事、一张场景封面和每位角色各一张画像；局部修订只生成需要替换的资源。不要额外添加场景图库或把制作任务改成应用内在线生图功能。
- 本地制作和检查可直接推进。上传、签名发布、推送或真机安装以用户本次请求及已有会话授权为准；调用 skill 本身不扩大外部操作权限。仅要求本地创作时，不自行发布。

## 创作与检查

写正文前读 [references/authoring.md](references/authoring.md)，对照当前 `StoryArchive` 类型和一个现有数据包确认格式。先定案发时间线、唯一致死者与排除链，再写三轮证据和各人剧本；避免先写气氛故事、最后硬补证据。

角色只能知道本人亲历、已获得资料或被明确告知的事实。真相、公开案情、本人知识、证言和对外说辞分开；公开简介与介绍不得泄底。用作者视角逐项核对真凶本人作案经历、证据引用、所有非凶手角色的可达性，以及每名无辜者被排除的依据。具体评审方法见 authoring 引用文件。

先在工作区内的草稿位置完成全文，再运行本 skill 的离线工具：

```bash
python3 <skill-dir>/scripts/story_tools.py check --repo <repo-root> --package <draft.json> --draft
```

修复实际报错并重新核对相关推理。检查通过不等于语义审稿或真实模型实玩通过；不伪造 `production` 审稿记录。外部模型审稿/实玩只在用户要求或已有明确授权范围内执行；失败或未执行时在交付记录中明确说明，继续可独立完成的工作。

## 生图与接入

文本可用后读 [references/artwork.md](references/artwork.md)，并按当前环境的 skill 目录读取 `imagegen/SKILL.md`。使用内置 `image_gen` / `imagegen` 工具，每个资源独立提示词和调用。无需项目 API key，不把全文、凶手标签或私密知识发给图像模型。

逐张目视检查后，用 `story_tools.py encode` 把工具返回的本地原图转换为版本化 WebP；建立 `artwork` 角色映射和精确提示词清单。不得用随机占位图宣称生图完成。工具不可用时报告缺图状态；不擅自切换 DashScope、付费 API 或读取项目生图密钥。

## 集成与交付

- 数据包放入 `backend/app/content/stories/<uuid>.json`，图片放入 `backend/app/content/images/<uuid>/`；新增文件加入源码 manifest。保持 `android-base.json` 原有基础包清单，兼容新增内容走下载，不为每个新故事重构 APK。
- 正文、元数据或配图变化都需提高已发布故事的 `metadata.version`；新文件名版本化，保留历史图片及其引用。新局用新包，旧局和复盘继续冻结版本，不改用户存档。
- 配图完成后运行 `story_tools.py check --repo <repo-root>`；按 authoring 引用文件执行相关现有回归，处理目录人数等真正受内容变更影响的断言，不降低校验来凑通过。
- 发布授权成立时，读 [references/publishing.md](references/publishing.md)，完成固定源码提交、签名包、远端核验和最后切换签名目录。缺少签名私钥或授权时保留完整本地成果与报告，不更换受信公钥，不用普通 JSON 冒充官方更新。
- 更新必要的目录、配图记录和制作验收记录；同步 CodeGraph。最终报告主题/标题、人数、版本、封面与画像数量、检查与实玩范围、文件位置及发布状态。可展示封面或一张代表画像，避免在普通交付说明中泄露谜底。
