# 剧本库与动态人物

## 已实现

首页默认进入“精选剧本”，可切换“我的剧本”和“自行生成”。内置故事在开局时只做本地加载，不触发在线审稿、重新生成或画像；AI 对话仍需联网与用户自己的 API key。

| 雨夜的最后一声钟 | 3 | 声音证言与客观时间 | 25 分钟 |

时长为设计估计。内置不等于所有模型下的人物表现已保证；自动流程测试使用模拟模型，不能替代真实玩家体验评审。

新制作支持自动决定 3—8 个角色，或指定 3—8 人。指定人数包含一名真人角色，NPC 数量为总人数减一；受害者不计入。自动模式由模型先规划人物关系再写正文。生成结果人数不符会在审稿前重试一次，仍不符就失败，不通过删除人物凑数。旧故事仍按其原人物列表运行，不对既有故事强制套用新制作范围。

## 内容文件与发布

内容位于 `backend/app/content/stories/`。`manifest.json` 明确列出随应用发布的包，构建只复制这个专用目录与原来明确指定的兼容剧本，不扫描用户存档。Web 后端和 APK 使用同一个包解析器。

每个包是一个 UTF-8 JSON 文件：

```json
{
  "format_version": 1,
  "metadata": {
    "schema_version": 1,
    "version": 1,
    "summary": "不包含谜底的公开简介",
    "difficulty": "入门",
    "estimated_minutes": 25,
    "author": "作者姓名",
    "license": "内容授权说明"
  },
  "archive": { "完整 StoryArchive": "见随附三个原创包" }
}
```

`archive` 的实际字段以 `StoryArchive.to_dict()` 为准，示例中的占位不能直接导入。可复制原创包了解完整结构。角色需要 `self_knowledge`、`objectives`；线索需要 `lead`、`discovery_round`，每轮必须有可获取的场景证据；`solution` 逐条引用实际证据原文。作者元数据不得写入凶手或秘密，只有这些公开元数据会出现在剧本列表。

增加内置故事：建立新的标准 UUID 剧本 ID、补齐完整数据包、将文件名加入 manifest，执行结构与全流程测试后发布。修订同一个故事：保留 UUID、增加 metadata.version、同步正文与证据链，再随新版 APK/后端发布。修改文件不改变已开始游戏。

## 导入与版本隔离

Web / Android 首页通过文件选择器导入 JSON；小程序通过微信文件选择导入，实际微信文件选择器尚需真机验证。接口为 `POST /stories/import`，请求 `{ "package": <完整数据包> }`。APK 使用相同服务的本地任务，无 HTTP 服务。

导入限 2 MB、3—8 角色、3—60 条线索，校验 UUID、格式版本、角色知识、持有权、引用、证据原文和三轮可达性。导入仅作结构与可达性检查，不运行在线语义审稿，不将包自称的“精品”或“已审稿”当作认证；统一标为“我的剧本 / imported”，忽略包宣称的 origin 与 production 来源。

相同内容的重复导入幂等返回，支持安装完成后丢失应答的恢复；不同内容的同版本和旧版本拒绝安装。同一个导入剧本只接受更高内容版本，原子替换本地成品文件；拒绝覆盖内置剧本或自行生成故事的 ID。导入官方内置内容的更新尚不支持，内置更新通过 APK/后端发布。远程目录、签名下载与自动更新未实现，后续可以沿用相同数据包格式扩展。

游戏快照 schema_version=4 包含完整 archive 和 catalog 元数据，重启优先使用该快照，不重新读取最新版。线索公开状态依然分开保存，成品 archive 始终不携带某局的公开进度。旧快照没有 archive 时仍按原 story_id 读取；下次保存会冻结当前读取的版本，无法追溯恢复升级前已经丢失的旧正文。旧成品文件不自动改写或重新审稿。

## 验证范围

后端测试覆盖三个本的所有非凶手人物，在经典与速推模式下完成搜证、对话、投票和揭晓，共 24 个角色/模式组合；检查全部作者证据可被调查。覆盖内置更新、导入更新、重启隔离、旧快照兼容、错误人数、引用与权限错误，以及导入来源冒充。安卓纯 Python 测试覆盖本地目录、导入与重启升级、无模型的非法人数拒绝、任务中断恢复。

这些验证证明结构与引擎流程，不证明审美质量或真实模型始终能正确扮演。内容继续升级前，应补充真实玩家反馈与真实模型的完整体验记录。

2026-10-03 已同签名覆盖安装 Redmi 2311DRK48C（Android16），三本目录、个人旧剧本、自动/3—8人选择与质量提示均可见，原8局公开存档摘要与密钥配置状态保留。修复首页滚动正文进入状态栏后复测旧讨论页和输入法弹出布局通过；没有新建手机测试局或发起模型请求，因此新增本的真实模型完整游玩仍待验证，Android文件选择器实际导入也未在本轮测试。详见 [安卓实施记录](android-port-plan.md)。

后续真实模型实玩已完成三本及雨夜v2复测，验收、修复与仍存在的回复降级见 [内置剧本实玩记录](builtin-story-playthrough.md)。雨夜现为内容版本2，增加带时戳的停机证据，已开的v1局继续保留原文。
