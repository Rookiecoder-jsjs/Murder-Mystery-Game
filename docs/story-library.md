# 剧本库与动态人物

## 已实现

首页默认进入“精选剧本”，可切换“我的剧本”和“自行生成”。内置故事在开局时只做本地加载，不触发在线审稿、重新生成或画像；AI 对话仍需联网与用户自己的 API key。

时长为设计估计。内置不等于所有模型下的人物表现已保证；自动流程测试使用模拟模型，不能替代真实玩家体验评审。

新制作支持自动决定 3—8 个角色，或指定 3—8 人。指定人数包含一名真人角色，NPC 数量为总人数减一；受害者不计入。自动模式由模型先规划人物关系再写正文。生成结果人数不符会在审稿前重试一次，仍不符就失败，不通过删除人物凑数。旧故事仍按其原人物列表运行，不对既有故事强制套用新制作范围。

## 内容文件与发布

内容位于 `backend/app/content/stories/`。`manifest.json` 明确列出源码内容；Android 构建以 `android-base.json` 选出首批三个基础包，其余通过官方内容包安装。构建只复制白名单与原来明确指定的兼容剧本，不扫描用户存档。Web 后端和 APK 使用同一个包解析器。

每个包是一个 UTF-8 JSON 文件：

```json
{
  "format_version": 1,
  "metadata": {
    "schema_version": 1,
    "version": 1,
    "summary": "不包含谜底的公开简介",
    "difficulty": "入门",
    "estimated_minutes": 25,
    "author": "作者姓名",
    "license": "内容授权说明"
  },
  "archive": { "完整 StoryArchive": "见随附原创包" }
}
```

`archive` 的实际字段以 `StoryArchive.to_dict()` 为准，示例中的占位不能直接导入。可复制原创包了解完整结构。角色需要 `self_knowledge`、`objectives`；线索需要 `lead`、`discovery_round`，每轮必须有可获取的场景证据；`solution` 逐条引用实际证据原文。作者元数据不得写入凶手或秘密，只有这些公开元数据会出现在剧本列表。

增加内置故事：建立新的标准 UUID 剧本 ID、补齐完整数据包、将文件名加入 manifest，执行结构与全流程测试后发布。修订同一个故事：保留 UUID、增加 metadata.version、同步正文与证据链，再发布更高内容版本的签名包；Web 后端仍使用源码 manifest。修改文件不改变已开始游戏。

## 导入与版本隔离

Web / Android 首页通过文件选择器导入 JSON；小程序通过微信文件选择导入，实际微信文件选择器尚需真机验证。接口为 `POST /stories/import`，请求 `{ "package": <完整数据包> }`。APK 使用相同服务的本地任务，无 HTTP 服务。

导入限 2 MB、3—8 角色、3—60 条线索，校验 UUID、格式版本、角色知识、持有权、引用、证据原文和三轮可达性。导入仅作结构与可达性检查，不运行在线语义审稿，不将包自称的“精品”或“已审稿”当作认证；统一标为“我的剧本 / imported”，忽略包宣称的 origin 与 production 来源。

相同内容的重复导入幂等返回，支持安装完成后丢失应答的恢复；不同内容的同版本和旧版本拒绝安装。同一个导入剧本只接受更高内容版本，原子替换本地成品文件；拒绝覆盖内置剧本或自行生成故事的 ID。普通 JSON 不能更新官方内容。Android 通过独立原生入口下载或离线安装受信 `.mmstory` 包，本地验签和原子提交后进入精选；个人与官方 ID 冲突拒绝。

官方内容独立更新已按 [协议与实施记录](story-content-updates.md) 实现：保留普通 JSON 个人导入，新增含正文与图片的签名 `.mmstory` 包，手机本地验证与原子安装，旧局继续使用冻结正文及历史图片。首次更新客户端后，兼容内容可独立交付，不需要每增加一个故事就重新构建 APK。

游戏快照 schema_version=4 包含完整 archive 和 catalog 元数据，重启优先使用该快照，不重新读取最新版。线索公开状态依然分开保存，成品 archive 始终不携带某局的公开进度。旧快照没有 archive 时仍按原 story_id 读取；下次保存会冻结当前读取的版本，无法追溯恢复升级前已经丢失的旧正文。旧成品文件不自动改写或重新审稿。

## 验证范围

后端测试按 manifest 覆盖所有本的非凶手人物，在经典与速推模式下完成搜证、对话、投票、揭晓及冻结存档恢复；六个本共 54 个角色/模式组合，检查全部作者证据可被调查。覆盖内置更新、导入更新、重启隔离、旧快照兼容、错误人数、引用与权限错误，以及导入来源冒充。安卓纯 Python 6 项测试覆盖三本基础内容加三个下载本、动态人数、导入与重启升级、旧正文迁移、无模型的非法人数拒绝、任务中断恢复。签名、ZIP、版本冲突和发布产物测试范围见内容更新记录。

这些验证证明结构与引擎流程，不证明审美质量或真实模型始终能正确扮演。内容继续升级前，应补充真实玩家反馈与真实模型的完整体验记录。
